# 블랙잭 (최대 6인) 설정 방법

오목과 마찬가지로 **로그인이 필수**입니다 — 여러 명이 같은 테이블에 앉는 게임이라
"이 자리가 누구였는지"를 새로고침 후에도 구분할 신원이 필요합니다. 계정 자체는
사이트 공용([../../firebase-config.js](../../firebase-config.js),
[../../auth.js](../../auth.js))을 그대로 씁니다 — 자세한 설정 방법은
[games/omok/README.md](../omok/README.md) / [games/crossword/README.md](../crossword/README.md)를
참고하세요.

## 칩은 계정에 저장되지 않습니다

테이블에 들어가는 순간 누구나 똑같이 1000칩(`STARTING_CHIPS`)으로 시작하고,
그 판이 끝나거나 테이블을 나가면 사라지는 **테이블 한정 칩**입니다. 계정의 누적
점수(`totalScore`)와는 전혀 별개이고, 칩이 0이 되면 다음 라운드 시작 시 자동으로
다시 1000으로 채워집니다 — "칩을 어떻게 벌어서 채우나"라는 문제 자체를 만들지
않기 위한 의도적인 단순화입니다.

## 오목과 다른 점: 히든 정보가 사실상 없음

실제 블랙잭 테이블에서도 딜러의 카드 한 장(홀 카드)을 제외하면 모든 사람의 패가
공개되어 있습니다 — 플레이어끼리 서로 카드를 숨길 필요가 없어요. 그래서 오목처럼
"본인만 읽을 수 있는 문서" 같은 걸 고민할 필요 없이, 테이블 문서 하나를 모두가
그대로 읽으면 됩니다. 딜러의 숨긴 카드도 그냥 문서에 값 자체는 들어있고
(`dealerRevealed: false`일 때) 클라이언트가 화면에 안 그려줄 뿐입니다 — 사이트
전체가 그렇듯 "완벽한 부정 방지"가 아니라 캐주얼한 친목용 신뢰 모델입니다.

## 진행 방식

1. 누군가 "새 테이블 만들기"를 누르면 6자리 코드를 가진 테이블이
   `blackjack-tables/{코드}` 문서로 만들어지고, 그 사람이 방장(host)이 됩니다.
2. 코드나 링크(`?table=코드`)를 공유하면 다른 사람들이 참가합니다 (최대
   `MAX_PLAYERS` = 6명, `waiting` 상태일 때만 참가 가능 — 라운드 진행 중에는
   중간 참가를 막습니다).
3. 방장이 "게임 시작"을 누르면 `betting` 상태가 되고, 각자 베팅액을 정해서
   "베팅 확정"을 누릅니다 (0을 확정하면 그 판은 쉽니다).
4. **모두가 베팅을 확정하면 방장의 클라이언트가 자동으로 카드를 돌립니다** —
   버튼이 따로 없고, 방장의 탭이 테이블 문서 변경을 실시간 구독하다가
   (`onSnapshot`) 마지막 사람이 베팅을 확정하는 순간 반응합니다. 그래서
   **방장의 탭이 계속 열려 있어야** 딜링/딜러 턴 진행이 됩니다 (아래 "알려진
   제약" 참고).
5. 순서대로 히트/스탠드/더블다운을 하고, 마지막 사람까지 끝나면 역시 방장의
   클라이언트가 딜러 턴을 자동 진행(17 이상이 될 때까지 뽑음)한 뒤 모든
   플레이어의 승패와 칩을 정산합니다.
6. "다음 판"으로 같은 테이블에서 바로 다시 시작할 수 있습니다.

## 알려진 제약 (의도적인 단순화)

- **방장이 딜러 로직의 유일한 실행자**입니다 (카드 분배, 딜러 턴 진행). 방장이
  탭을 닫으면 그 시점 이후 진행이 멈춥니다 — Cloud Functions 없는 캐주얼
  사이트라 서버 쪽 권위자가 없고, 오목의 "1대1이라 재연결만 처리하면 됨"보다
  한 단계 더 신뢰가 필요한 지점입니다. 나중에 필요하면 "방장이 없으면 다음
  사람이 이어받기" 같은 걸 추가할 수 있습니다.
- **딜러의 블랙잭 사전 확인(peek)을 하지 않습니다** — 실제 카지노는 딜러가
  에이스/10을 보여주면 블랙잭인지 미리 확인해서 즉시 라운드를 끝내지만, 여기는
  단순화를 위해 항상 모든 플레이어가 먼저 다 끝난 뒤 딜러 턴을 진행합니다.
- **스플릿(같은 숫자 페어를 나눠 두 손으로 플레이)은 없습니다.** 히트/스탠드/
  더블다운만 지원합니다.
- **딜러는 17 이상이면 무조건 멈춥니다** (소프트 17 히트 같은 변형 규칙 없음).

## Firestore 보안 규칙 (추가분)

기존 [games/crossword/README.md](../crossword/README.md)의 규칙에 아래
`blackjack-tables` 블록을 **같은 `match /databases/{database}/documents { ... }`
안에** 추가하세요.

```
match /blackjack-tables/{tableId} {
  allow read: if true;
  allow create: if request.auth != null
                && request.resource.data.hostUid == request.auth.uid
                && request.resource.data.status == "waiting"
                && request.resource.data.playerOrder.size() == 1
                && request.resource.data.playerOrder[0] == request.auth.uid;
  // 이미 앉아있는 사람만 쓸 수 있고, 예외적으로 "아직 안 앉아있지만 이번
  // 쓰기로 자기 자신을 참가시키는" 경우(참가 액션)도 허용합니다. 오목
  // 규칙과 같은 이유로 이번이 정말 내 차례가 맞는지, 카드가 정말 그렇게
  // 나왔는지까지는 규칙에서 검증하지 않습니다 -- 클라이언트 로직(방장만
  // 딜링/딜러 턴 실행, 본인 uid 필드만 히트/스탠드로 갱신)과 "로그인한
  // 사람만, 이 테이블에 실제로 앉은 사람만 쓸 수 있다"가 이 캐주얼
  // 게임의 실질적 방어선입니다.
  allow update: if request.auth != null
                && (
                  request.auth.uid in resource.data.playerOrder
                  || (
                    !(request.auth.uid in resource.data.playerOrder)
                    && request.auth.uid in request.resource.data.playerOrder
                    && resource.data.status == "waiting"
                  )
                );
}
```

규칙을 아직 안 붙였거나 Firebase 설정 자체가 안 돼 있으면, 블랙잭 페이지는
로그인 필요 안내 화면만 보여주고 조용히 멈춥니다 (다른 게임이 깨지지 않습니다).
