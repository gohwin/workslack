# 원카드 (2~6인) 설정 방법

블랙잭/오목과 마찬가지로 **로그인이 필수**입니다 — 여러 명이 같은 테이블에 앉는
게임이라 "이 자리가 누구였는지"를 새로고침 후에도 구분할 신원이 필요합니다.
계정 자체는 사이트 공용([../../firebase-config.js](../../firebase-config.js),
[../../auth.js](../../auth.js))을 그대로 씁니다 — 자세한 설정 방법은
[games/omok/README.md](../omok/README.md) / [games/crossword/README.md](../crossword/README.md)를
참고하세요. 블랙잭과 달리 봇 모드는 없습니다 — 원카드는 최소 2명이 있어야 성립하는
게임이라 "혼자서 딜러랑" 같은 개념이 없고, v1은 사람끼리 하는 버전만 만들었습니다.

## 손패 보안: 사이트 기존 방식과 동일 (완벽한 비공개 아님)

실제로 안전하게 손패를 숨기려면 각자 손패를 본인만 읽을 수 있는 별도 Firestore
문서로 분리하고 보안 규칙도 그렇게 걸어야 합니다. 하지만 이 사이트가 지금까지
써온 방식(오목의 보드, 블랙잭의 테이블 전체 — 딜러의 숨긴 카드 포함)은 전부
**캐주얼한 친목용 신뢰 모델**입니다: 문서 하나를 모두가 그대로 읽되, 클라이언트가
화면에 보여주지 않을 뿐입니다. 원카드도 똑같이 만들었습니다 — 모든 사람의 손패,
덱, 버린 패가 전부 `onecard-tables/{코드}` 문서 하나 안에 그대로 들어있고,
`renderTable()`이 본인(`currentUser`) 손패만 앞면으로 그리고 다른 사람 손패는
카드 뒷면(장수만)으로 그립니다. 개발자 도구를 열면 이론상 다른 사람 패를 다 볼 수
있습니다 — 블랙잭의 딜러 히든카드와 똑같은 수준의 (안) 보안입니다.

## 게임 규칙 (v1, 의도적으로 단순화)

표준 카드 52장(조커 없음)을 씁니다. 각자 7장씩 받고, 나머지가 덱(뽑을 패)이
됩니다. 내 차례에 낸 카드가 버린 패 맨 위 카드와 **무늬나 숫자가 같으면** 낼 수
있습니다. 못 내거나(또는 그냥) 안 내고 싶으면 "뽑기"로 한 장 뽑고 턴이 넘어갑니다.

특수 카드 (딱 세 종류만, 최대한 단순하게):

- **A**: 다음 사람 턴을 건너뜁니다.
- **2**: 다음 사람이 2장을 뽑고 턴이 건너뜁니다.
- **J**: 진행 방향이 반대로 바뀝니다. (2명이서 할 땐 방향을 바꿔도 항상 상대방
  차례로 돌아오는 건 똑같아서 사실상 효과가 없습니다 — 일부 하우스룰처럼
  "1대1에서는 반전이 스킵으로 취급"하는 예외는 넣지 않았습니다.)

빠진 것들 (의도적으로 안 만듦):

- **와일드/무늬 변경 카드 없음** (8이나 조커로 무늬 바꾸는 규칙 없음).
- **2 중첩 없음** — 2 위에 2를 얹어서 4장 뽑기로 넘기는 룰은 없습니다.
- **"원카드!" 콜/페널티 없음** — 한 장 남았을 때 외쳐야 하는 하우스룰은
  구현하지 않았습니다.
- **낼 수 있으면 반드시 내야 하는 강제 없음** — 낼 수 있는 카드가 있어도 그냥
  뽑기를 선택할 수 있습니다. "낼 수 있는 카드가 정말 하나도 없는지" 서버에서
  검증하는 로직을 안 만들어서 생기는 자유도입니다.
- **가장 먼저 손패를 비운 사람만 승자** — 2등/3등을 가리지 않고 라운드가 바로
  끝납니다.
- 시작 패 뒤집었을 때 특수 카드(A/2/J)가 나오면 다시 뽑아서 일반 카드가 나올
  때까지 반복합니다 (아무도 턴을 안 가진 상태에서 효과를 적용할 대상이 없어서).

## 진행 방식

1. 누군가 "새 테이블 만들기"를 누르면 6자리 코드를 가진 테이블이
   `onecard-tables/{코드}` 문서로 만들어지고, 그 사람이 방장(host)이 됩니다.
2. 코드나 링크(`?table=코드`)를 공유하면 다른 사람들이 참가합니다 (최대
   `MAX_PLAYERS` = 6명, 최소 `MIN_PLAYERS` = 2명, `waiting` 상태일 때만 참가
   가능).
3. 방장이 "게임 시작"을 누르면 각자에게 7장씩 나눠지고 첫 턴이 시작됩니다.
4. 순서대로 카드를 내거나 뽑습니다. **카드를 내는 동작은 오목의 돌 놓기처럼
   Firestore 트랜잭션으로 처리됩니다** — 방장 권위자 없이 매 턴마다 그 순간의
   실제 차례인 사람이 직접 서버 최신 상태를 다시 확인하고 씁니다 (블랙잭의
   히트/스탠드보다 한 단계 더 안전한 방식 — 카드 내는 액션이 여러 필드를 한 번에
   건드리고, 상대방 손패까지 건드릴 수 있는 2 카드 효과가 있어서).
5. 누군가 손패를 다 비우면 그 사람이 승리하고 라운드가 끝납니다. "다음 판"으로
   같은 테이블에서 바로 다시 시작할 수 있습니다.

## 알려진 제약

- 위 "게임 규칙" 섹션에 적은 단순화 목록 전부.
- 나가기(`leaveTable()`)는 실제로 자리를 비웁니다 — 방장이 나가면 다음 사람이
  방장이 되고, 내 차례에 나가면 다음 사람에게 턴이 넘어갑니다 (블랙잭에 나중에
  추가된 것과 같은 패턴). 다만 블랙잭의 하트비트/방치 자리 회수 기능은 없습니다
  — 원카드는 아직 공개 테이블 목록이 없어서(비공개 코드/링크 참가만) 방치된
  자리가 영구히 못 쓰게 될 걱정이 덜합니다.

## Firestore 보안 규칙 (추가분)

아래 `onecard-tables` 블록을 `match /databases/{database}/documents { ... }`
안에 추가하세요 (블랙잭 규칙과 구조가 거의 동일합니다):

```
match /onecard-tables/{tableId} {
  allow read: if true;
  allow create: if request.auth != null
                && request.resource.data.hostUid == request.auth.uid
                && request.resource.data.status == "waiting"
                && request.resource.data.playerOrder.size() == 1
                && request.resource.data.playerOrder[0] == request.auth.uid;
  // 블랙잭 규칙과 같은 이유로 "이번이 정말 내 차례가 맞는지, 카드가 정말
  // 손패에 있었는지, 무늬/숫자가 정말 맞는지"까지는 규칙에서 검증하지
  // 않습니다 -- 클라이언트 로직(트랜잭션으로 매 액션마다 서버 최신 상태
  // 재확인)과 "로그인한 사람만, 이 테이블에 실제로 앉은 사람만 쓸 수
  // 있다"가 이 캐주얼 게임의 실질적 방어선입니다.
  allow update: if request.auth != null
                && (
                  request.auth.uid in resource.data.playerOrder
                  || (
                    !(request.auth.uid in resource.data.playerOrder)
                    && request.auth.uid in request.resource.data.playerOrder
                    && resource.data.status == "waiting"
                  )
                );
}
```

규칙을 아직 안 붙였거나 Firebase 설정 자체가 안 돼 있으면, 원카드 페이지는
로그인 필요 안내 화면만 보여주고 조용히 멈춥니다 (다른 게임이 깨지지 않습니다).
